# 飛機 {#aircraft}

本頁供想知道飛機欄位從哪裡來、該有多信任的讀者閱讀。下面每項檢查，都是把一個數值拿來和回放檔以另一種獨立方式說明的值比對；這裡只列出方法與吻合程度。

## 座艙儀表 {#cockpit-instruments}

訊息 0xD04A 會以（編號, 數值）成對的方式送出錄製玩家的儀表：競技戰鬥中每秒四筆，模擬戰鬥中只送有變動的數值。這些編號在所有座艙之間組成同一份清單，每個座艙只送它的機型有的儀表。哪個編號對應哪個儀表是由遊戲程式決定的，所以每個編號都是依它的作用來命名，再拿回放檔來核對（`convert.INSTRUMENTS` 存放結果；內容不是從安裝目錄讀取的）：

| 編號 | 名稱 | 核對對象 |
|---|---|---|
| 0 | 指示空速，m/s | 經空氣密度修正後的航跡速度：相關係數 0.99 |
| 39 | 爬升率，m/s | 航跡的爬升率：相關係數高於 0.99 |
| 40, 41 | 高度，m；高度除以 1000 的餘數 | 航跡的高度，相差幾公尺 |
| 52, 53 | 人工地平儀的橫滾與俯仰 | 負的表格橫滾與俯仰，相差不到 1 度 |
| 64 | 羅盤 | 表格的航向，相差不到 0.1 度 |
| 15-20 | 方向舵踏板 | 飛機所受的側向力 |
| 23, 31 | 操縱桿：升降舵與副翼（正負號依座艙模型） | 攻角；橫滾速率 |
| 69, 71, 73 | 時鐘：時（12 小時制錶面）、分、秒 | 錄製電腦的當地時間，精確到分 |
| 75 | 進氣歧管壓力，atm | 在戰爭緊急動力時比全油門時高 |
| 81-86, 87-92, 93-98 | 每具引擎的轉速、轉速除以 1000 的餘數、轉速表 | 彼此完全相同；引擎轉速：相關係數高於 0.97 |
| 195 | 燃油 | 一趟出擊中逐漸下降，重生時回到滿油 |
| 228-230 | 起落架三支腿，1 表示放下 | 只在接近機場的高度、且速度夠低時才放下 |
| 240, 241 | 每具引擎的油門（1.1 表示戰爭緊急動力或加力燃燒室） | 飛行紀錄項目中的油門 |
| 330-332, 346-348 | 彈藥計數器（兩組相同） | 武器預設的發數，隨飛行紀錄項目的發數減少 |
| 135, 159 | 機油溫度與汽缸頭溫度 | 可能：一趟出擊中會升高 |
| 58, 61 | 側滑球、轉彎針 | 可能：會跟隨側向力與轉彎速率 |
| 223 | 減速板 | 可能：只在進場時設定 |
| 490-497, 500-505 | 輪煞車 | 可能：只在機場地面靜止時設定 |

另外還有一些編號有送出，但含義不明；它們保存在回放紀錄的 `authorInstruments.notNamed` 中。

表格中的 `ias`、`vario`、`fuel`、`manifoldPressure`、`gear`、`oilTemperature`、`headTemperature` 與 `throttle` 就是由這些數值來的，取自錄製玩家自己的列；取樣前最多 0.2 秒內的最後一則訊息。

## 飛行紀錄項目 {#flight-entries}

每架飛機的飛行紀錄項目（封包類型 2）除了位置與姿態之外，還包含：

- **速度**：姿態之後的一個 32 位元字。第 31、30、29 位元分別是 x、y、z 的正負號；接著是 11 位元的速率，單位為 500/2047 m/s（到 500 m/s 就停止）；再來是 |x| 與 |y|，各以 9 位元表示為速率的比例；z 則由讓向量成為單位向量而算出。與收到的相鄰取樣之間的位移相比：錄製玩家的方向誤差在幾分之一度內，其他人則在約 2 度內；速率誤差在 0.2% 內。見 `selfCheck.flightEntries`。
- **每種武器的發數**：位置之前的一個清單，每種武器一項，先放剩餘發數。錄製玩家的發數，幾乎每次取樣都等於座艙計數器晚一個時間刻度的數值。
- **操縱與油門**：速度之後的 7 個位元組，以 14 個半位元組（nibble）讀取。對錄製玩家而言，每個時間刻度都有：1 為升降舵，2 為副翼，3 為方向舵（靜止時為 8），11 為油門，以十五分之一為單位（戰爭緊急動力與加力燃燒室時也是 15），4 為輪煞車，5 為減速板，8 可能是煞車傘。其他飛機的半位元組一場戰鬥中只會變化幾次，而且不代表它們當時的操縱。
- **引擎**：每具引擎有一個狀態位元組（0 關閉；1-6 啟動中；7 運轉中；8 故障）、一個 16 位元的數值（只在加力燃燒室時送出，32767 為全開），以及一個只在引擎被擊中後才有的位元組。引擎進入「故障」的大多數飛機，都會在幾分鐘內被擊毀或結束。

## 反射資料 {#reflection-data}

訊息 0xF02D 與 0xF0AA 會複製遊戲中有編號的物件：每個物件有一個 id（前 5 位元為種類，後 11 位元為索引）與一張欄位表。種類 14 是玩家位置（欄位 2 為使用者 id 與名稱，欄位 9 為隊伍），種類 15 是隊伍（索引 1 與 2）：

- 位置的欄位 39 在固定位置存放它的統計：擊殺（偏移 0）、隊友擊殺（2）、死亡（4）、海上擊殺（10）、AI 擊殺（12）、AI 地面擊殺（14）、助攻（20）、佔領點（22）、區域傷害（24，32 位元）、傷害獎勵（40，32 位元）、導彈規避（50）。欄位 38 開頭是分數，欄位 42 是小隊。戰鬥結束時，每位玩家的每個數值都與結算結果相同（`selfCheck.scoreboardVsResults`）。地面擊殺記在哪裡，目前不知道。
- 隊伍的欄位 7 是它的分數：結束時等於結算中各玩家分數的總和。欄位 3 可能是它的票數。
- 每則訊息只送有變動的欄位，因此回放紀錄中的 `scoreboard` 會在每次變動時列出每位玩家的統計與每個隊伍的分數。

## 航位推算與平滑器 {#dead-reckoning-and-the-smoother}

客戶端回放會每秒記錄每架飛機四次，即客戶端畫出的樣子。在遠處飛機的兩次更新之間，客戶端會依它最後的速度把它往前移，並依它最後的角速率轉動；到下一次更新時再把它直接跳到該處。照原樣讀取，航跡會是直線，然後跳動。飛行紀錄項目中沒有任何東西標示哪些取樣是收到的；航位推算的取樣是依它的特徵找出的：它會延續前兩個取樣的直線，速度相同，誤差在 3 公分內。

這件事的影響程度取決於戰鬥類型：競技戰鬥中，其他飛機約有一半的取樣可以用航位推算得出；模擬戰鬥中只有幾個百分點。平滑器會把超過 15 g 的跳動減少約五倍（`selfCheck.deadReckoning`）。錄製玩家自己的飛機不會被客戶端外推，保持原樣。

預設情況下（`--no-smoothing` 可關閉），除了錄製玩家以外所有單位的航跡，都會放在收到的狀態所指示的位置：航位推算的取樣會落在它前後收到的取樣之間的曲線上，每個取樣各自帶有自己的速度；超過 3 秒的時候，直線只會朝下一個收到的取樣彎曲，因此沒有任何取樣移動超過客戶端自己的跳動幅度。它的姿態會從一個收到的姿態平均地轉到下一個。收到的取樣最多會以 2 公尺或 0.04 秒的速度做平滑；穩定的轉彎則維持原樣。回放自己的數值仍保留在 `Raw` 欄位中。

## 姿態核對 {#attitude-checked}

在錄製玩家自己的飛機上，航向（中位數）與飛行方向相差一度以內，俯仰與爬升角相差幾度以內；在明顯的轉彎中，幾乎每個取樣的橫滾都與轉彎方向的正負號相同：飛行模型的橫滾是左翼向下為正，而表格則改為右翼向下為正（`selfCheck.aircraftAttitude`）。10 位元角度的步進為 0.18 度。地面單位的姿態則以它們的射擊來核對（[砲塔](ground.md#turrets)）。
