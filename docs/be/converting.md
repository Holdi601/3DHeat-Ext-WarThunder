# Канвертаванне запісаў {#converting-replays}

Вынік: адзін файл `.3dheat` на бой (па змаўчанні) або асобныя файлы з
`--loose`.

## Крок за крокам {#step-by-step}

1. **Уключыце запісы.** War Thunder захоўвае запісы кліента ў папцы
   `Replays` гульні, калі ў яе наладах уключана захаванне запісаў, напрыклад
   `C:\Program Files (x86)\Steam\steamapps\common\War Thunder\Replays`.
   Таксама можна канвертаваць запіс сервера, захаваны са старонкі запісаў
   гульні (zip з `0000.wrpl`, `0001.wrpl`, ...).
2. **Адкрыйце тэрмінал** у папцы, куды можна класці вынікі
   ([Перад пачаткам](before-you-start.md)).
3. **Канвертуйце:**

   ```bash
   heat3d-wt-replay "<War Thunder>/Replays" -o out
   heat3d-wt-replay a.wrpl b.wrpl -o out           # files, folders, or both
   heat3d-wt-replay battle.zip -o out              # a server replay's zip
   heat3d-wt-replay a.wrpl -o out --loose          # separate files instead of one .3dheat
   ```

   `out` ствараецца ў папцы, у якой знаходзіцца ваш тэрмінал.
4. **Прачытайце, што ён піша.** Вы павінны ўбачыць па радку на кожны бой.
5. **Адкрыйце:** загрузіце `out/<map>/<match>.3dheat` у праглядальніку 3DHeat
   ([Loading one](https://holdi601.github.io/3DHeat/container.html#loading-one)).

![Запуск на сінтэтычным запісе: адзін .3dheat, --loose, пашкоджаны файл, пустая папка](../assets/img/convert.svg)

Малюнак паказвае запуск на запісе, які тэсты будуюць у кодзе (ніякага
сапраўднага запісу, ніякай усталёўкі гульні):

- `ok <file>`: бой сканвертаваны (з `--loose`: `ok <table> <match document>`);
- `failed <file>: <why>`: файл, які не ўдалося прачытаць (статус выхаду 1;
  астатнія ўсё роўна канвертуюцца);
- `no .wrpl files given`: няма чаго канвертаваць (статус выхаду 2);
- `note: ...`: напрыклад, што ўсталёўку War Thunder для назваў машын не
  знойдзена.

## Параметры {#options}

| Параметр | Па змаўчанні | Што робіць |
|---|---|---|
| `replays` (адзін або болей) | - | файлы `.wrpl`, папкі з імі (сама папка, не яе падпапкі) або zip з імі (запіс сервера: яго часткі `.wrpl` распакоўваюцца ў часовую папку) |
| `-o`, `--out` | абавязковы | куды пісаць: усярэдзіне па папцы на кожную карту |
| `--game FOLDER` | знаходзіцца | папка War Thunder, тэкст якой даюць назвы машын, зброі і боепрыпасаў, а табліцы - цэны для [эканомікі](economy.md); таксама `HEAT3D_WT_GAME` |
| `--no-smoothing` | выкл. | пакідае экстрапаляваныя і атрыманыя адлікі іншых адзінак такімі, як у запісе ([Экстрапаляцыя](aircraft.md#dead-reckoning-and-the-smoother)) |
| `--container` | укл. | упакоўвае кожны бой у адзін файл `.3dheat` |
| `--loose` | выкл. | пакідае кожны бой асобнымі файламі (табліца, дакумент матча, дапаможныя файлы) |
| `--version` | - | выводзіць `heat3d-wt-replay <version>` і спыняецца |
| `-h`, `--help` | - | выводзіць параметры і спыняецца |

Бой, канвертаваны паўторна, запісваецца паўторна. Параметры ў тым выглядзе,
як іх друкуе праграма: [Даведнік каманд](../cli-reference.md).

## Якія файлы складаюць адзін бой {#which-files-are-one-battle}

Кожны бой становіцца адным файлам,
`out/<map>/<map>_<AB|RB|SB>_<mode>_<start, UTC>_<session id>.3dheat`. AB, RB
і SB - скарочаныя назвы гульні для аркадных, рэалістычных і сімулятарных
баёў; `<mode>` - рэжым місіі пад тым ключом, які выкарыстоўвае гульня
(`Conq4` Conquest #4, `Dom` Domination, `Bttl` Battle; гл.
[Рэжым бою](ground.md#battle-mode)); любая з частак прапускаецца, калі запіс
яе не называе. Часткі запісу сервера (`0000.wrpl`, `0001.wrpl`, ...)
чытаюцца разам як адзін бой; запіс кліента і часткі сервера таго ж бою - гэта
два запісы, і яны застаюцца двума.

## Статус выхаду {#exit-status}

`0`, калі кожны бой сканвертаваны, `1`, калі хоць адзін не ўдаўся (астатнія
ўсё роўна канвертуюцца), `2`, калі сярод аргументаў не знойдзена ніводнага
файла запісу.
