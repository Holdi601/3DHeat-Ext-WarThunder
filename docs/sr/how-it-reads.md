# Како чита реплеј {#how-it-reads-a-replay}

Ова страница је за људе који желе да знају шта конвертор чита, како је проверено, и
колико треба веровати свакој колони. За претварање реплеја не треба вам.

Читање је проверено на клијентским реплејима ваздушних аркадних, ваздушних
симулаторских и поморских битки, на серверским реплејима копнених битака, и, за
распореде из 2025, на јавним примерним реплејима
[wt_replay_decoder](https://github.com/llama-for3ver/wt_replay_decoder).
Свака провера пореди вредност с нечим што реплеј каже на други, независан начин;
овде се даје само метод и слагање.

## Шта се чита, и провера {#what-is-read-and-the-check}

| Део | Стање, и провера |
|---|---|
| Заглавље, мапа, мисија, време почетка, сесија; резултати | свака датотека |
| Подешавања мисије (blk после заглавља) | режим, време, границе, `stars` (датум, време, место) |
| Низ пакета (zlib 2025, zstd 2026) | сваки пакет уоквирен |
| Позиције и став авиона (распоред 2026) | 4 узорка у секунди, ниједан пакет неочитан; правац се слаже са смером кретања |
| Пакети лета испред свог времена | после застоја у мрежи, пакет лета клијентског реплеја понекад држи сваки други авион тамо где ће бити око 0,75 s касније. Предњачење се мери по пакету, и сваки авион који предњачи добија време које представља (`selfCheck.flightPacketsRetimed`) |
| Скокови мртвог рачунања | корак из низа мртвог рачунања мери се од последњег примљеног стања, па клијентске исправке више не секу трајекторије ([Мртво рачунање](aircraft.md#dead-reckoning-and-the-smoother)) |
| Телепортовања | трак се сече где јединица иде брже него што може: прво према својој врсти (авион 750 m/s, копно и бродови 40 m/s, оружје 1800 m/s), па према сопственом темпу. Сваки рез је наведен у `trackBreaks` са вероватним узроком (оживљавање, игра помера играча, исправка удаљене јединице). Након резова, ниједан корак између редова трака није бржи него што врста дозвољава (`selfCheck.stepSpeed`) |
| Позиције копна и бродова (0xF073 / 0xF074) | ниједан пакет неочитан. Правац, нагиб и валљање из става од 16 битова: правац се слаже са смером кретања у оквиру око 2 степена (медијана); нагиб броји 180/65536 степена по кораку; с окренутим знаком валљања, правац топа из трупа и торња показује на погођену јединицу за скоро сваки пуцањ тенка. Бродови стоје на нивоу воде |
| Торњеви | заокрет торња и нагиб топа тенкова: видите [Торњеве](ground.md#turrets) |
| Спаковане висине копна | позиције спаковане у 64 бита броје висину од -100 m на већини нивоа, а од нивоа воде на неким; помак се мери на сваком реплеју из јединица виђених у оба облика (`selfCheck.packedGroundHeight`) |
| Ток ентитета (стварање, уништење) | свако стварање прочитано. Распоред долази из објављеног извора Dagor Engine-а; компоненте типова War Thunder-а сопствене се прескачу тако што се налази где почиње следећа компонента. Возило и слот играча сваке јединице једнаки су онима које именују записи убистава и погодака, за сваки проверен запис |
| Ко је возио коју јединицу, AI јединице, бродови, копнене мете | из тока ентитета: свака јединица има своје возило и тим, јединица сваког играча свог играча |
| Убиства према резултатима | смрти по играчу једнаке су онима из резултата; резултати броје више убистава, јер клијенту није послато свако убиство. Реплеј који почиње након почетка битке држи само убиства после тога |
| Убиства, критични погоци, тешка штета | свака датотека |
| Уништени модули (0xF118) | јединица и број дела; име дела треба модел оштећења возила, а он није у реплеју |
| Испуштено оружје (ток ентитета) | тачка испуштања је неких 10-20 m (медијана) од најближе јединице, која се узима као лансер |
| Оружје у лету (0xF0DB) | ракете, пројектили и бомбе, сваки везан за свој ентитет |
| Бомбе без записа о лету | бомба без њих добија пад израчунат од испуштања до удара (гравитација и отпор, узорак на сваких 0,1 s, `extrapolated` true). Проверено над морем, где је висина удара позната: израчунати падови завршавају у оквиру око 15 m од воде. У документу меча такво оружје има `ballisticImpact`; `counts.bombsBallistic` их броји |
| Места играча, ћаскање | свака датотека |
| Експлозије, рафали ПВО, награде, откривања, време, објекти мисије | прочитано; положаји проверени оком у приказачу |
| Мерачи кабине снимајућег играча (0xD04A) | именовани по томе шта раде: [Инструменти у кабини](aircraft.md#cockpit-instruments); остали под `notNamed` |
| Остала поља уноса лета | брзина, меци, управљање, мотори: [Уноси лета](aircraft.md#flight-entries) |
| Став у редовима догађаја | сваки ред догађаја носи правац, нагиб, валљање и вектор гледања своје јединице у том тренутку |
| Статистика играча и резултати тимова | на крају битке свака статистика једнака је оној из резултата за сваког играча: [Подаци рефлексије](aircraft.md#reflection-data) |
| Називи оружја и возила | из енглеске локализације ваше инсталације; неки подразумевани појасеви бродова и радари аеродрома немају назив у игри |
| Играчи и AI | ниједан ред играча из резултата није AI, сваки ред који није AI је играч из резултата (`selfCheck.identity`) |
| Олупине | узорци јединице после њене смрти настављају да пристижу; олупина копнене јединице или брода је `alive` 0 док се њен ентитет не уклони, и остаје један трак; авиони држе `alive` 0 највише 60 s (`selfCheck.wrecks`) |
| Промене возила | ако је играчева јединица још жива кад се следећа његова јединица појави, прва се ту завршава (возило остављено на месту). `selfCheck.vehicleSwitch.twoLiveVehicles` мора бити 0 |
| Режим битке | [Режим битке](ground.md#battle-mode) |
| Авиони у серверском реплеју 2026 | читају се у распореду 2026; правац и знак валљања се слажу с окретима; лажни авиони и извиђачки дронови не носе податке |
| Играчи серверског реплеја | нађени по имену у слотовима; свака статистика једнака је оној из резултата (`selfCheck.players`) |
| Авиони у серверским реплејима 2025 и верзији 101286 | нису читани: њихови пакети лета имају други распоред |

## Поруке упућене јединицама {#messages-to-units}

Сваки пакет типа 4 је mpi порука Dagor Engine-ове daNet: ид објекта примаоца, па
(кад су његових 11 доњих битова сви постављени) проширени UID објекта, ид поруке и
корисни терет. Порука јединици носи као свој проширени UID ид ентитета јединице,
`index << 10 | generation`. Проверено: свака таква порука именује ентитет који је
тада био жив.

За стручњаке, поруке које се читају:

| Порука | Шта, и провера |
|---|---|
| 0xF0E9 UnitHitEffects | погодак једног пројектила: UID стрелца и тачка поготка у систему јединице (x напред, y горе, z лево): центиметри код авиона и бродова, 20/32768 m по кораку код копнених јединица (прилагођено величини торњева тенкова). `hitLocalX/Y/Z` у метрима. Постаје ред `shot` ([Паљба](hits.md#gunfire)). Стрелац скоро сваког записа о погоку и убиству је међу овим стрелцима; тачке погодака леже на страни окренутој стрелцу |
| 0xF133 UnitOnExplosion | исти UID стрелца |
| 0xF04B OnUnitDead | редови `dead`: жртва сваког записа о убиству има један у року од 2 s |
| 0xD047 FmwRpm | обртаји мотора (`rpm`); слаже се с мерачем обртаја кабине |
| 0xF0B1, 0xF0A0 | редови `gun_shot`: појединачни пуцњи тешке ПВО и артиљерије |
| 0xF01B, 0xF01C | редови `fire_start`, `fire_stop`: рафали 40 mm ПВО топова (пуцање топа; пожар на возилу је `fire_on`, видите [Пожари на возилу](hits.md#vehicle-fires)) |
| 0xF050, 0xF033, 0xF054, 0xF0BD, 0xD046 | редови `bailout`, `repair`, `rearm`, `bullet_rearm`, `reload` |
| 0xD0FE ProjectileHitReplay | сопствени погоци снимајућег играча и погађање њега, с оружјем и муницијом, именовани из инсталације (`projectileHitReplays`) |
| 0xF13E, 0xF031 | визуелни ефекат погодка и ефекат пуштен на јединици; долазе с поготком на истој јединици |
| 0xD041 | по један за сваки одбрамбени топ авиона, два пута у секунди; њихови индекси се слажу с оружјима стрелаца из модела лета |
| 0xD048, 0xF117 | распоред прочитан, значење није познато |
| остале (0xF09A, 0xD020, 0xF015, 0xF04F, ...) | у пратећој датотеци порука, с јединицом и пољима |

Називи су из заједнице (ShioUmiusi/WTACRP, `tools/wrpl_mpi_names.py`).

## Такође се чита {#also-read}

- **Репликација тока ентитета** (0x22, 0x23): по ентитету блок вредности компоненти:
  тајмери поправке брода, бројеви потрошног материјала, промене власника и тима,
  прегревање мотора. Бројано у `counts.replicatedComponents`; вредности у пратећој
  датотеци порука.
- **Радње скрипте мисије** (0xF028) и **савети** (0xF0EC): `triggers`, `hints`.
  **Напредак мисије** (0xF07A, 0xF07C): `missionProgress`.
- **Реплеј камера** (0xD043): видите [Камеру](ground.md#the-camera).

## Није прочитано, и зашто {#not-read-and-why}

- **Називи и тела порука ентитета** (0x20, 0x21): број класе је место на списку
  уграђеном у игру, не шаље се и није у њеним подацима. Две се читају (пожари возила
  и њихове гасилице); остале се чувају целе са својим ентитетом и бројем класе.
- **Остали репликовани објекти** (врсте осим места играча и тимова): прочитани и
  сачувани, не именовани; нема у резултатима с чим да се провере.
- **Управљање, гас и меци туђих авиона**: освежавају се само повремено; чувају се у
  пратећој датотеци лета, не у табели.
- **Пожари на авионима**: нису нађени ни у једној поруци; авион у пламену нема ред
  `fire_on`.
- **Имена испуштеног оружја**: ентитет бомбе или ракете не држи име; записи убистава
  именују оружје којим је убиство учињено.
- **Пуцњи који су промашили**: реплеј држи само погоке.

`counts.messageIdsNotRead` и `selfCheck` документа меча кажу шта нови реплеј држи и
колико је добро прочитан.
