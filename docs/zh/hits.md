# 命中、射击与火灾 {#hits-gunfire-and-fires}

本页面向想了解命中、弹药和火灾各列数据从何而来的读者。核对部分只给出方法和一致程度。

## 射击 {#gunfire}

录像中包含每一枚命中了单位的弹丸（消息 0xF0E9）：一条 `shot` 行，位于命中瞬间射手的位置；`targetX/Y/Z` 为命中点（被命中的单位，按其坐标系中的命中点移动，并经其姿态转换）；方向指向该点；`other` 为被命中的单位。未命中的炮弹和子弹不会被发送：它们不是实体，而飞行中武器的消息只包含火箭弹、导弹、炸弹和鱼雷。录像播放者剩余的弹数（其 `ammo` 列）会随着射击而减少，因此可以分辨它的射击段，但无法得知这些弹药飞向了何处。重型高射炮和火炮会分别发送每一发射击（`gun_shot`，没有方向），40 毫米高射炮则发送它们的连发（`fire_start`、`fire_stop`）。

## 命中结果 {#hit-outcomes}

每当弹丸命中地面单位时，服务器会向该单位发送消息 0xF144（UnitOnHit）：四个单字节字段，第四个字段的各个位表示该次命中的效果（`selfCheck.unitMessages.outcome_*`）：

| 位 | 含义 | 依据 |
|---|---|---|
| 0x20 | 弹丸本身的命中 | 几乎全部都在 5 毫秒之内伴随一次对该单位的 0xF0E9 命中而出现；没有它时，则伴随一次爆炸（溅射） |
| 0x01 | 穿透了装甲（穿甲） | 所有带有 0x02、0x04 或 0x08 的消息也都带有它 |
| 0x02 | 致命命中（要害） | 大多数要害命中的记录都带有它，其出现频率远高于随机水平 |
| 0x04 | 摧毁 | 大多数伴随击杀记录，并且该单位在一秒内死亡 |
| 0x08 | 严重损伤 | 部分要害命中的记录带有它；其他情况较少见 |

`hitOutcome` 取其中最严重的结果：`kill`（0x04）、`critical`（0x02 或 0x08）、`penetration`（0x01）、`nonpenetration`（仅 0x20）。每次命中会与其单位在 5 毫秒之内、最近的、尚未配对的带 0x20 的 0xF144 配对。游戏的命中镜头可以区分跳弹与未穿透，但这里找到的任何位或字段都无法做到这一点：前三个字节在每次命中之间都会变化，其含义未知。客户端录像只为录像播放者自己的飞机发送 0xF144，且所有位均为零：飞机和舰船的命中没有结果。

## 弹药 {#ammunition}

（`selfCheck.unitMessages.ammunition`）

* **是否为爆炸性弹药。** 会爆炸的炮弹会发送 0xF133（UnitOnExplosion），其中包含射手的 uid 和该次命中的编号；带有它的命中为 `explosive`，其余为 `kinetic`（动能）。
* **火炮及其弹槽。** 0xF0BD（UnitBulletRearm）表示下一发装填的弹药：武器在载具武器列表中的索引、弹药槽位以及剩余弹数。手动装填手的装填会在每次命中之后经过一段稳定的装填时间才出现，自动炮的则在零点几秒之后出现。射手的命中按载具、特征和连发分组；当某武器在其一半或以上的命中之后 20 秒之内、以稳定的延迟装填一发弹时，该组即属于该武器。`ammoSlot` 的格式为 `武器/槽位`，即命中之前装填的那个槽位：很可能就是被射击的那一个，除非玩家在此期间更换了弹药。机枪不发送 0xF0BD。
* **炮弹。** 击杀所用武器是炮弹的 ID（`125mm_3bm46`）；击杀者对受害者的最后一次命中，会将其归到该射手的槽位上，前提是火炮口径相符。炮弹的类型和口径取自武器文件（`bulletName`、`bulletType`、`caliber`；`apds_fs_*` 为 APFSDS，`heat_fs_*` 为 HEAT-FS，`he_*` 为 HE……）。
* **其余命中的口径。** 取该槽位武器的口径；机枪组则取其特征所能对应的唯一一种机枪口径；否则取载具主炮的口径。没有安装目录（`--game`）时，除 `explosive` / `kinetic` 之外，没有类型、名称或口径信息。

未找到的内容：跳弹。另有几条消息带有命中的射手和编号（0xF0C2，很可能是命中镜头在载具内的路径；0xF117、0xF13C、0xF13E）；它们保存在附属文件中，但没有被解码。未穿透的命中仍然标记为 `nonpenetration`。

## 载具火灾 {#vehicle-fires}

着火的载具会向所有客户端显示：每当列表发生变化时，服务器都会向该载具发送一条实体消息（事件 `0a519c58`），列出正在该载具上燃烧的火源。对每个火源，包含两个 16 位 ID（第二个是损伤模型的节点）、其种类，以及在火源点燃之前为 -1。由命中点燃的火源，还会收到一条消息，给出其燃烧点在载具坐标系中的位置（x 为前方，y 为上方，z 为左侧）。

各行：火源出现在列表中时为 `fire_on`，消失时为 `fire_off`，都位于载具处，并包含 `fireId`（`第一个:节点`）、`fireKind`，以及对于由命中点燃的火源，还有 `fireLocalX/Y/Z`（前、上、右）。载具一旦被摧毁，其列表往往不会再次发送：其火源随其残骸结束，否则随其实体结束，再否则随录像结束（`selfCheck.fires`）。

核对结果：每次坦克的灭火器数量减少时，都会有一个火源在零点几秒之内从列表中消失；大多数火源位置都位于点燃它的那次命中所在的同一侧。火源的种类以数字表示；它们代表什么尚不清楚，节点对应哪个部件也不清楚。飞机不发送此类列表：着火的飞机无法被读取。
