# 飞机 {#aircraft}

本页面向想知道飞机各列数据从何而来、以及这些数据可信度如何的读者。下面每项检查，都会把某个数值与录像以另一种独立方式给出的结果进行比较；这里只写明方法和一致程度。

## 座舱仪表 {#cockpit-instruments}

消息 0xD04A 以（编号，数值）对的形式发送录像播放者的仪表：在街机战斗中每秒四次，在模拟战斗中只发送有变化的数值。所有座舱的编号构成同一个列表，每个座舱只发送其模型所具有的仪表。游戏代码决定了每个编号对应哪个仪表，因此每个编号都是根据它的作用来命名的，并与录像进行了核对（结果保存在 `convert.INSTRUMENTS` 中；没有从游戏安装中读取任何内容）：

| 编号 | 名称 | 核对方式 |
|---|---|---|
| 0 | 指示空速，m/s | 飞机轨迹的速度经空气密度修正后：相关系数 0.99 |
| 39 | 爬升率，m/s | 轨迹的爬升率：相关系数高于 0.99 |
| 40, 41 | 高度，m；高度对 1000 取模 | 轨迹的高度，相差几米 |
| 52, 53 | 人工地平线的横滚和俯仰 | 取表格横滚和俯仰的负值，相差不到 1 度 |
| 64 | 罗盘 | 表格的航向，相差不到 0.1 度 |
| 15-20 | 方向舵踏板 | 作用在飞机上的侧向力 |
| 23, 31 | 操纵杆：升降舵和副翼（符号与座舱模型一致） | 迎角；滚转率 |
| 69, 71, 73 | 时钟：小时（12 小时制表盘）、分钟、秒 | 录像计算机的本地时间，精确到分钟 |
| 75 | 进气歧管压力，atm | 在战时紧急动力下高于全油门时 |
| 81-86, 87-92, 93-98 | 每台发动机的转速，转速对 1000 取模，转速表 | 彼此完全相同；发动机转速：相关系数高于 0.97 |
| 195 | 燃油 | 在一次出击中下降，重生时重新加满 |
| 228-230 | 起落架的各腿，1 表示放下 | 仅在接近机场的高度和着陆速度时放下 |
| 240, 241 | 每台发动机的油门（1.1 表示战时紧急动力或加力燃烧室） | 飞行记录中的油门 |
| 330-332, 346-348 | 弹药计数器（两组相同） | 武器预设的弹数，并随飞行记录中的弹数减少 |
| 135, 159 | 机油和气缸盖温度 | 很可能：它们在一次出击中会上升 |
| 58, 61 | 侧滑球，转弯针 | 很可能：它们跟随侧向力和转弯率 |
| 223 | 减速板 | 很可能：只在进近时设置 |
| 490-497, 500-505 | 车轮刹车 | 很可能：只在机场地面静止时设置 |

还有一些编号会被发送，但其含义未知；它们保存在对局文档的 `authorInstruments.notNamed` 中。

表格中的 `ias`、`vario`、`fuel`、`manifoldPressure`、`gear`、`oilTemperature`、`headTemperature` 和 `throttle` 都来自这些仪表：取录像播放者自己的行，使用采样后最多 0.2 秒内的最后一条消息。

## 飞行记录 {#flight-entries}

每架飞机的飞行记录（数据包类型 2）除了位置和姿态外，还包含：

- **速度**：姿态之后的一个 32 位字。第 31、30、29 位分别是 x、y、z 的符号；然后是 11 位的速度，单位为 500/2047 m/s（最大到 500 m/s 为止）；接着是 |x| 和 |y|，分别以速度的比例表示，各占 9 位；z 的值则使向量成为单位向量。已用相邻接收采样之间的变化进行核对：录像播放者的方向误差在不到一度之内，其他所有人的方向误差在约 2 度之内；速度误差在 0.2% 之内。见 `selfCheck.flightEntries`。
- **每种武器的弹数**：位于位置之前的一个列表，每种武器一项，先给出剩余弹数。录像播放者的弹数，在几乎所有采样中都等于一个节拍之后的座舱计数器。
- **操纵和油门**：速度之后的 7 个字节，按 14 个半字节（nibble）读取。对于录像播放者，每个节拍都有：1 为升降舵，2 为副翼，3 为方向舵（静止时为 8），11 为油门（以十五分之一计，战时紧急动力和加力燃烧室时也为 15），4 为车轮刹车，5 为减速板，8 很可能是减速伞。其他飞机的半字节在一场战斗中只会变化几次，并且并不代表它们当时的操纵。
- **发动机**：每台发动机有一个状态字节（0 为关闭；1-6 为启动中；7 为运行中；8 为损坏），一个 16 位的数值（仅在加力燃烧室时使用，32767 为全功率），以及一个仅在发动机被命中后才出现的字节。发动机显示“损坏”的大多数飞机，都会在几分钟内被击毁或结束。

## 反射数据 {#reflection-data}

消息 0xF02D 和 0xF0AA 复制了游戏中带编号的对象：对每个对象，给出它的 ID（前 5 位是类型，后 11 位是索引）以及一个字段表。类型 14 为玩家槽位（字段 2 为用户 ID 和名称，字段 9 为队伍），类型 15 为队伍（索引 1 和 2）：

- 槽位的字段 39 在固定位置保存其统计数据：击杀（偏移 0）、队友击杀（2）、死亡（4）、海上击杀（10）、AI 击杀（12）、AI 地面击杀（14）、助攻（20）、占领区（22）、占领区伤害（24，32 位）、伤害奖励（40，32 位）、导弹规避（50）。字段 38 以得分开头，字段 42 为小队。一场战斗结束时，每个数值都与结果中的数值一致，适用于每一位玩家（`selfCheck.scoreboardVsResults`）。地面击杀记录在哪里，目前尚不清楚。
- 队伍的字段 7 是其得分：战斗结束时，它等于结果中该队所有玩家得分之和。字段 3 很可能是其兵力点数。
- 每条消息只发送发生变化的字段，因此对局文档中的 `scoreboard` 会在每次变化时列出所有玩家的统计数据和所有队伍的得分。

## 航位推算与平滑器 {#dead-reckoning-and-the-smoother}

客户端录像会以每秒四次的频率记录每架飞机，即客户端绘制时的状态。在两次更新之间，对于收到的远处飞机的更新，客户端会沿其最后的速度移动它，并以其最后的转动率使其转向；到下一次更新时，再把它直接跳到那里。如果原样读取，轨迹会是直线，然后突然跳跃。飞行记录中没有任何标记说明哪些采样是收到的；被航位推算的采样，是通过其特征识别的：它延续了前两个采样的直线，并且速度与之相同，误差在 3 厘米之内。

这一点的影响大小取决于对局类型：在街机战斗中，其他飞机的采样中约有一半可以被航位推算；在模拟战斗中，只有百分之几。平滑器可以把超过 15 g 的跳变减少约五倍（`selfCheck.deadReckoning`）。录像播放者自己的飞机不会被客户端外推，因此保持原样。

默认情况下（`--no-smoothing` 可以关闭它），除录像播放者自己的单位之外，所有单位的轨迹都会放在收到的状态所指示的位置：被航位推算的采样会落在一条曲线上，该曲线穿过它之前和之后收到的采样，每个采样都带有自己的速度；超过 3 秒后，直线只会朝向下一个收到的采样弯曲，因此任何采样都不会比客户端自身的跳变移动得更远。其姿态会从一个收到的姿态均匀地转到下一个收到的姿态。收到的采样最多会按其速度平滑 2 米或 0.04 秒；稳定的转弯保持不变。录像自身的数值保留在 `Raw` 列中。

## 姿态核对 {#attitude-checked}

对于录像播放者自己的飞机，航向与行进方向的差距（中位数）在一度之内，俯仰与爬升角的差距在几度之内；在明显的转弯中，几乎每个采样的横滚符号都与转弯方向一致：飞行模型的横滚以左翼下沉为正，而表格则以右翼下沉为正（`selfCheck.aircraftAttitude`）。10 位角度的步长为 0.18 度。地面单位的姿态则通过它们的射击进行核对（[炮塔](ground.md#turrets)）。
