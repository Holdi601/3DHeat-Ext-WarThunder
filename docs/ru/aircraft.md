# Самолёты {#aircraft}

Для читателей, которые хотят знать, откуда берутся столбцы самолётов и насколько им можно
доверять. Каждая проверка ниже сравнивает значение с тем, что реплей говорит другим,
независимым способом; здесь приведены только метод и совпадение.

## Приборы кабины {#cockpit-instruments}

Сообщение 0xD04A присылает приборы игрока, который записал реплей, как пары (номер, значение):
четыре раза в секунду в аркадных боях, только изменившиеся значения в симуляторных боях.
Номера образуют один список для всех кабин, а кабина присылает те приборы, которые есть в её
модели. Код игры задаёт, какой номер соответствует какому прибору, поэтому каждый номер был
назван по тому, что он делает, и сверен с реплеем (`convert.INSTRUMENTS` содержит результат;
из установки ничего не читается):

| Номер | Название | Сверено с |
|---|---|---|
| 0 | индикаторная воздушная скорость, м/с | скорость трека, поправленная на плотность воздуха: корреляция 0.99 |
| 39 | вертикальная скорость, м/с | вертикальная скорость трека: корреляция выше 0.99 |
| 40, 41 | высота, м; высота по модулю 1000 | высота трека, с разницей в несколько метров |
| 52, 53 | крен и тангаж искусственного горизонта | минус крен и тангаж таблицы, с разницей меньше 1 градуса |
| 64 | компас | курс таблицы, с разницей меньше 0.1 градуса |
| 15-20 | педали руля направления | боковая сила на самолёте |
| 23, 31 | ручка: руль высоты и элероны (знак как у модели кабины) | угол атаки; угловая скорость крена |
| 69, 71, 73 | часы: часы (12-часовой циферблат), минуты, секунды | местное время компьютера записи, с точностью до минуты |
| 75 | давление наддува, атм | выше на боевом аварийном режиме, чем на полном газе |
| 81-86, 87-92, 93-98 | обороты по каждому двигателю, обороты по модулю 1000, тахометр | друг друга точно; обороты двигателя: корреляция выше 0.97 |
| 195 | топливо | падает за вылет, снова полное при возрождении |
| 228-230 | стойки шасси, 1 — выпущено | выпущено только на высоте аэродрома и на посадочной скорости |
| 240, 241 | газ по каждому двигателю (1.1 — боевой аварийный режим или форсаж) | газ записи полёта |
| 330-332, 346-348 | счётчики боеприпасов (два одинаковых набора) | снаряды набора оружия, убывающие вместе со снарядами записи полёта |
| 135, 159 | температура масла и головок цилиндров | вероятно: растут за вылет |
| 58, 61 | шарик скольжения, стрелка поворота | вероятно: следуют за боковой силой и угловой скоростью поворота |
| 223 | воздушный тормоз | вероятно: включается только на заходе на посадку |
| 490-497, 500-505 | колёсные тормоза | вероятно: включаются только стоя на аэродроме |

Некоторые другие номера присылаются, но их значение не известно; они сохраняются в
`authorInstruments.notNamed` документа матча.

Столбцы таблицы `ias`, `vario`, `fuel`, `manifoldPressure`, `gear`, `oilTemperature`,
`headTemperature` и `throttle` берутся отсюда, из строк самого игрока, который записал
реплей: берётся последнее сообщение не позже чем за 0.2 с до выборки.

## Записи полёта {#flight-entries}

Запись полёта каждого самолёта (тип пакета 2) содержит, помимо положения и ориентации:

- **Скорость**: 32-битное слово после ориентации. Биты 31, 30 и 29 — знаки x, y и z; затем
  скорость в 11 битах по 500/2047 м/с (дальше 500 м/с не идёт), затем |x| и |y| как доли
  скорости по 9 битов каждая, а z — то, что делает вектор единичным. Сверено с шагом между
  полученными выборками: направление совпадает в пределах доли градуса для игрока, который
  записал реплей, и в пределах около 2 градусов для всех остальных; скорость — в пределах
  0.2 %. `selfCheck.flightEntries`.
- **Снаряды по каждому оружию**: список перед положением, по одному элементу на оружие,
  сначала остаток снарядов. У игрока, который записал реплей, он почти для каждой выборки
  равен счётчикам кабины на один такт позже.
- **Управление и газ**: 7 байт после скорости, прочитанные как 14 полубайтов. Для игрока,
  который записал реплей, на каждом такте: 1 — руль высоты, 2 — элероны, 3 — руль направления
  (8 в покое), 11 — газ в пятнадцатых (15 также для боевого аварийного режима и форсажа), 4 —
  колёсные тормоза, 5 — воздушный тормоз, 8 — вероятно, тормозной парашют. Полубайты других
  самолётов меняются лишь несколько раз за бой и не являются их управлением в тот момент.
- **Двигатели**: по каждому двигателю байт состояния (0 — выключен; 1-6 — запуск; 7 — работает;
  8 — мёртв), 16-битное значение только при форсаже (32767 — полный), и байт только после
  попадания в двигатель. Большинство самолётов, у которых двигатель стал «мёртвым», сбиваются
  или заканчивают бой в течение минут.

## Данные отражения {#reflection-data}

Сообщения 0xF02D и 0xF0AA реплицируют пронумерованные объекты игры: для каждого объекта его
id (старшие 5 битов — вид, младшие 11 — индекс) и таблица полей. Вид 14 — слоты игроков
(поле 2 — id пользователя и имя, 9 — команда), вид 15 — команды (индексы 1 и 2):

- Поле 39 слота содержит его статистику на фиксированных местах: убийства (смещение 0),
  убийства своей команды (2), смерти (4), морские убийства (10), убийства ИИ (12), убийства
  наземного ИИ (14), помощь (20), зоны захвата (22), урон по зонам (24, 32-битное), премия за
  урон (40, 32-битная), уклонения от ракет (50). Поле 38 начинается с очков, поле 42 — отряд.
  В конце боя каждое значение равно значению из результатов для каждого игрока
  (`selfCheck.scoreboardVsResults`). Где хранятся убийства наземной техники, не известно.
- Поле 7 команды — её очки: в конце оно равно сумме очков её игроков в результатах. Поле 3,
  вероятно, — её билеты.
- Каждое сообщение присылает только изменившиеся поля, поэтому `scoreboard` в документе матча
  перечисляет статистику каждого игрока и очки каждой команды при каждом изменении.

## Счисление пути и сглаживание {#dead-reckoning-and-the-smoother}

Клиентский реплей записывает каждый самолёт четыре раза в секунду так, как его нарисовал
клиент. Между обновлениями, которые клиент получает для удалённого самолёта, клиент продолжает
двигать его по его последней скорости и поворачивает по последним угловым скоростям, а при
следующем обновлении переносит его на место. Прочитанный как есть, трек идёт прямо, а потом
прыгает. В записи полёта ничего не отмечает, какие выборки были получены; выборку по счислению
узнают по её виду: она продолжает прямую из двух предыдущих выборок с их скоростью, с
точностью до 3 см.

Насколько это важно, зависит от боя: в аркадных боях около половины выборок чужих самолётов
может быть получено по счислению, в симуляторных — лишь несколько процентов. Сглаживание
уменьшает скачки больше 15 g примерно в пять раз (`selfCheck.deadReckoning`). Собственный
самолёт игрока, который записал реплей, клиент не экстраполирует, поэтому он остаётся таким,
какой есть.

По умолчанию (`--no-smoothing` выключает это) треки всех юнитов, кроме собственного самолёта
игрока, который записал реплей, ставятся туда, где их по полученным состояниям и было:
выборка по счислению ложится на кривую через полученные выборки до и после неё, каждая со
своей скоростью; на протяжении более 3 с прямая лишь изгибается к следующей полученной
выборке, поэтому никакая выборка не уходит дальше собственного скачка клиента. Ориентация
равномерно поворачивается от одной полученной ориентации к следующей. Полученные выборки
сглаживаются не более чем на 2 м или 0.04 с их скорости; устойчивый поворот остаётся как есть.
Значения самого реплея остаются в столбцах `Raw`.

## Ориентация, проверено {#attitude-checked}

У собственного самолёта игрока, который записал реплей, курс совпадает с направлением движения
в пределах одного градуса (медиана), тангаж — в пределах нескольких градусов от угла набора
высоты, а при явных поворотах крен имеет знак поворота почти для каждой выборки: крен модели
полёта положителен при левом крыле вниз, а таблица переводит его в положительный при правом
крыле вниз (`selfCheck.aircraftAttitude`). 10-битные углы шагают по 0.18 градуса. Ориентацию
наземных юнитов сверяют по их выстрелам ([Башни](ground.md#turrets)).
