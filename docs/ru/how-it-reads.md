# Как читается реплей {#how-it-reads-a-replay}

Эта страница для тех, кто хочет знать, что читает преобразователь, как это проверено и
насколько можно доверять каждому столбцу. Для преобразования реплеев она не нужна.

Чтение проверено на клиентских реплеях аркадных воздушных, симуляторных воздушных и морских
боёв, на серверных реплеях наземных боёв и, для раскладок 2025 года, на публичных образцах
реплеев из [wt_replay_decoder](https://github.com/llama-for3ver/wt_replay_decoder). Каждая
проверка сравнивает значение с тем, что реплей говорит другим, независимым способом; здесь
приведены только метод и совпадение.

## Что читается и как проверено {#what-is-read-and-the-check}

| Часть | Статус и проверка |
|---|---|
| Заголовок, карта, задание, время начала, сессия; результаты | каждый файл |
| Настройки задания (blk после заголовка) | режим, погода, лимиты, `stars` (дата, время, место) |
| Поток пакетов (zlib в 2025, zstd в 2026) | каждый пакет разобран по границам |
| Положения и ориентация самолётов (раскладка 2026) | 4 выборки в секунду, ни один пакет не остаётся непрочитанным; курс совпадает с направлением движения |
| Пакеты полёта, опережающие своё время | после сетевого сбоя пакет полёта клиентского реплея иногда содержит положение каждого чужого самолёта там, где он будет примерно через 0.75 с. Опережение измеряется для каждого пакета, и каждому опережающему самолёту присваивается время, которое он представляет (`selfCheck.flightPacketsRetimed`) |
| Скачки счисления | шаг из серии по счислению измеряется от последнего полученного состояния, поэтому поправки клиента больше не разрывают треки ([Счисление пути](aircraft.md#dead-reckoning-and-the-smoother)) |
| Телепортации | трек разрывается там, где юнит перемещается дальше, чем может: сначала по его виду (самолёт 750 м/с, наземная техника и корабли 40 м/с, оружие 1800 м/с), затем по его собственному темпу. Каждый разрыв перечислен в `trackBreaks` с его вероятной причиной (возрождение, игра переместила игрока, поправка далёкого юнита). После разрывов ни один шаг между строками трека не быстрее, чем допускает его вид (`selfCheck.stepSpeed`) |
| Положения наземной техники и кораблей (0xF073 / 0xF074) | ни один пакет не остаётся непрочитанным. Курс, тангаж и крен по 16-битной ориентации: курс совпадает с направлением движения в пределах около 2 градусов (медиана); тангаж считается шагами по 180/65536 градуса; при повернутом знаке крена направление пушки от корпуса и башни попадает в поражённый юнит почти для каждого выстрела танка. Корабли стоят на уровне воды |
| Башни | поворот башен танков и наклон пушки: см. [Башни](ground.md#turrets) |
| Упакованные высоты наземных юнитов | положения, упакованные в 64 бита, отсчитывают высоту от -100 м на большинстве уровней и от уровня воды на некоторых; смещение измеряется в каждом реплее по юнитам, которые видны в обеих формах (`selfCheck.packedGroundHeight`) |
| Поток сущностей (создание, уничтожение) | каждое создание прочитано. Раскладка взята из опубликованного исходного кода Dagor Engine; собственные типы компонентов War Thunder пропускаются, находя, где начинается следующий компонент. Техника и слот игрока каждого юнита совпадают с теми, которые называют записи об убийствах и попаданиях, для каждой проверенной записи |
| Кто управлял каким юнитом, юниты ИИ, корабли, наземные цели | из потока сущностей: у каждого юнита есть своя техника и команда, у юнита каждого игрока — его игрок |
| Убийства по сравнению с результатами | смерти по игрокам равны результатам; результаты учитывают больше убийств, так как клиенту присылаются не все убийства. Реплей, который начинается после начала боя, содержит только убийства после этого момента |
| Убийства, критические попадания, тяжёлые повреждения | каждый файл |
| Уничтоженные модули (0xF118) | юнит и номер части; название части требует модели повреждений техники, которой в реплее нет |
| Отпущенное оружие (поток сущностей) | точка отпуска находится примерно в 10-20 м (медиана) от ближайшего юнита, который принимается за пусковую установку |
| Оружие в полёте (0xF0DB) | управляемые ракеты, ракеты и бомбы, каждая связана со своей сущностью |
| Бомбы без записей полёта | бомба без них получает падение, вычисленное от отпуска до удара (гравитация и сопротивление, выборка каждые 0.1 с, `extrapolated` true). Проверено над морем, где высота удара известна: вычисленные падения заканчиваются в пределах около 15 м от воды. В документе матча у такого оружия есть `ballisticImpact`; `counts.bombsBallistic` считает их |
| Слоты игроков, чат | каждый файл |
| Взрывы, очереди зенитного огня, награды, обнаружения, погода, объекты задания | прочитаны; положения проверены глазом в просмотрщике |
| Приборы игрока, который записал реплей (0xD04A) | названы по тому, что они делают: [Приборы кабины](aircraft.md#cockpit-instruments); остальные — в `notNamed` |
| Другие поля записей полёта | скорость, снаряды, управление, двигатели: [Записи полёта](aircraft.md#flight-entries) |
| Ориентация строк событий | каждая строка события содержит курс, тангаж, крен и вектор взгляда её юнита в тот момент |
| Статистика игроков и очки команд | в конце боя каждый показатель каждого игрока равен результатам: [Данные отражения](aircraft.md#reflection-data) |
| Названия оружия и техники | из английской локализации вашей установки; у некоторых стандартных поясов кораблей и радаров аэродромов в игре нет названия |
| Игроки и ИИ | ни одна строка игрока из результатов не является ИИ, каждая строка не-ИИ — игрок из результатов (`selfCheck.identity`) |
| Обломки | выборки юнита после его смерти продолжают приходить; обломок наземной техники или корабля имеет `alive` 0, пока его сущность не удалена, и остаётся одним треком; самолёты сохраняют `alive` 0 не дольше 60 с (`selfCheck.wrecks`) |
| Смены техники | живая техника игрока, которая ещё жива, когда появляется следующая техника того же игрока, завершается в этот момент (техника, оставленная стоять). `selfCheck.vehicleSwitch.twoLiveVehicles` должно быть 0 |
| Режим боя | [Режим боя](ground.md#battle-mode) |
| Самолёты в серверном реплее 2026 | читаются в раскладке 2026; курс и знак крена совпадают с поворотами; самолёты-заглушки и разведывательные дроны не несут данных |
| Игроки серверного реплея | находятся по имени в слотах; каждый показатель равен результатам (`selfCheck.players`) |
| Самолёты в серверных реплеях 2025 и версии 101286 | не читаются: их пакеты полёта имеют другую раскладку |

## Сообщения юнитам {#messages-to-units}

Каждый пакет типа 4 — это сообщение mpi из daNet Dagor Engine: id объекта-адресата, затем (когда
его младшие 11 битов все установлены) расширенный UID объекта, id сообщения и полезная нагрузка.
Сообщение юниту несёт в качестве расширенного UID id его сущности, `index << 10 | generation`.
Проверено: каждое такое сообщение называет сущность, живую в этот момент.

Для специалистов, сообщения читаются так:

| Сообщение | Что и проверка |
|---|---|
| 0xF0E9 UnitHitEffects | попадание одного снаряда: uid стрелявшего и точка попадания в системе координат юнита (x вперёд, y вверх, z влево): сантиметры у самолётов и кораблей, 20/32768 м на шаг у наземных юнитов (подогнано под размер башен танков). `hitLocalX/Y/Z` в метрах. Становится строкой `shot` ([Стрельба](hits.md#gunfire)). Стрелявший почти каждого попадания и записи об убийстве есть среди этих стрелявших; точки попадания лежат на стороне, обращённой к стрелявшему |
| 0xF133 UnitOnExplosion | тот же uid стрелявшего |
| 0xF04B OnUnitDead | строки `dead`: у жертвы каждой записи об убийстве есть такая строка в пределах 2 с |
| 0xD047 FmwRpm | обороты двигателей (`rpm`); совпадает с тахометром кабины |
| 0xF0B1, 0xF0A0 | строки `gun_shot`: одиночные выстрелы тяжёлых зениток и артиллерии |
| 0xF01B, 0xF01C | строки `fire_start`, `fire_stop`: очереди 40-мм зениток (орудие стреляет; пожар на технике — это `fire_on`, см. [Пожары техники](hits.md#vehicle-fires)) |
| 0xF050, 0xF033, 0xF054, 0xF0BD, 0xD046 | строки `bailout`, `repair`, `rearm`, `bullet_rearm`, `reload` |
| 0xD0FE ProjectileHitReplay | собственные попадания игрока, который записал реплей, и попадания по нему, с оружием и боеприпасами, названными по установке (`projectileHitReplays`) |
| 0xF13E, 0xF031 | визуальный эффект попадания и эффект, проигранный на юните; они приходят вместе с попаданием в тот же юнит |
| 0xD041 | по одному на каждое оборонительное орудие самолёта, дважды в секунду; их индексы совпадают с оружием стрелков модели полёта |
| 0xD048, 0xF117 | раскладка прочитана, значение не известно |
| остальные (0xF09A, 0xD020, 0xF015, 0xF04F, ...) | во вспомогательном файле сообщений, с их юнитом и полями |

Названия — из сообщества (ShioUmiusi/WTACRP, `tools/wrpl_mpi_names.py`).

## Также читается {#also-read}

- **Репликация потока сущностей** (0x22, 0x23): для каждой сущности блок значений компонентов:
  таймеры ремонта кораблей, счётчики расходуемых предметов, смены владельца и команды,
  перегрев двигателя. Учитывается в `counts.replicatedComponents`; значения — во вспомогательном
  файле сообщений.
- **Действия сценария задания** (0xF028) и **подсказки** (0xF0EC): `triggers`, `hints`.
  **Ход задания** (0xF07A, 0xF07C): `missionProgress`.
- **Камера реплея** (0xD043): см. [Камера](ground.md#the-camera).

## Не читается, и почему {#not-read-and-why}

- **Названия и тела сообщений сущностей** (0x20, 0x21): номер класса — это место в списке,
  скомпилированном в игру; он не присылается и не содержится в её данных. Два читаются (пожары
  техники и её огнетушители); остальные сохраняются целиком с их сущностью и номером класса.
- **Другие реплицированные объекты** (виды, отличные от слотов игроков и команд): читаются и
  сохраняются, но не называются; в результатах нет ничего, с чем их можно было бы сверить.
- **Управление, газ и снаряды других самолётов**: обновляются только время от времени; хранятся
  во вспомогательном файле полёта, а не в таблице.
- **Пожары самолётов**: ни в одном сообщении не найдены; у горящего самолёта нет строки
  `fire_on`.
- **Названия отпущенного оружия**: в сущности бомбы или ракеты нет названия; записи об убийствах
  называют оружие убийства.
- **Выстрелы, которые промахнулись**: реплей содержит только попадания.

`counts.messageIdsNotRead` и `selfCheck` каждого документа матча говорят, что содержит новый
реплей и насколько хорошо он прочитан.
