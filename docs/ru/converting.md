# Преобразование реплеев {#converting-replays}

Результат: один файл `.3dheat` на бой (по умолчанию) или отдельные файлы с `--loose`.

## Пошагово {#step-by-step}

1. **Включите запись реплеев.** War Thunder сохраняет клиентские реплеи в папку
   `Replays` игры, если в её настройках включено сохранение реплеев, например
   `C:\Program Files (x86)\Steam\steamapps\common\War Thunder\Replays`.
   Серверный реплей, сохранённый со страницы реплеев игры (архив с `0000.wrpl`,
   `0001.wrpl`, ...), тоже можно преобразовать.
2. **Откройте терминал** в папке, куда можно записать результаты
   ([Перед началом](before-you-start.md)).
3. **Преобразуйте:**

   ```bash
   heat3d-wt-replay "<War Thunder>/Replays" -o out
   heat3d-wt-replay a.wrpl b.wrpl -o out           # файлы, папки или и то и другое
   heat3d-wt-replay battle.zip -o out              # архив серверного реплея
   heat3d-wt-replay a.wrpl -o out --loose          # отдельные файлы вместо одного .3dheat
   ```

   Папка `out` создаётся в папке, где открыт ваш терминал.
4. **Прочитайте, что написано в выводе.** На каждый бой должна быть одна строка.
5. **Откройте результат:** загрузите `out/<map>/<match>.3dheat` в просмотрщике 3DHeat
   ([Как загрузить](https://holdi601.github.io/3DHeat/container.html#loading-one)).

![Запуск на синтетическом реплее: один .3dheat, --loose, испорченный файл, пустая папка](../assets/img/convert.svg)

Картинка показывает запуск на реплее, который строят тесты в коде (ни настоящего
реплея, ни установки игры не нужно):

- `ok <file>`: бой преобразован (с `--loose`: `ok <table> <match document>`);
- `failed <file>: <why>`: файл не удалось прочитать (код завершения 1; остальные всё
  равно преобразуются);
- `no .wrpl files given`: нечего преобразовывать (код завершения 2);
- `note: ...`: например, что установка War Thunder не найдена, поэтому техника не
  получила названий.

## Параметры {#options}

| Параметр | По умолчанию | Что делает |
|---|---|---|
| `replays` (один или несколько) | - | файлы `.wrpl`, папки с ними (сама папка, а не её подпапки) или архивы с ними (серверный реплей: его части `.wrpl` распаковываются во временную папку) |
| `-o`, `--out` | обязательный | куда писать: внутри создаётся папка на каждую карту |
| `--game FOLDER` | находится сама | папка War Thunder, из текстов которой берутся названия техники, оружия и боеприпасов и по таблицам которой оценивается [экономика](economy.md); также `HEAT3D_WT_GAME` |
| `--no-smoothing` | выключен | оставлять выборки других единиц, построенные по счислению, и полученные выборки такими, какие они есть в реплее ([Счисление пути](aircraft.md#dead-reckoning-and-the-smoother)) |
| `--container` | включён | упаковать каждый бой в один файл `.3dheat` |
| `--loose` | выключен | сохранять каждый бой отдельными файлами (таблица, документ матча, вспомогательные файлы) |
| `--version` | - | вывести `heat3d-wt-replay <version>` и остановиться |
| `-h`, `--help` | - | вывести параметры и остановиться |

Бой, преобразованный повторно, записывается заново. Параметры в том виде, как их
выводит программа: [Справка по командам](../cli-reference.md).

## Какие файлы относятся к одному бою {#which-files-are-one-battle}

Каждый бой становится одним файлом
`out/<map>/<map>_<AB|RB|SB>_<mode>_<start, UTC>_<session id>.3dheat`. AB, RB и SB —
короткие обозначения игры для аркадных, реалистичных и симуляторных боёв; `<mode>` —
режим задания так, как его обозначает игра (`Conq4` — Завоевание №4, `Dom` —
Доминирование, `Bttl` — Битва; см. [Режим боя](ground.md#battle-mode)). Любая из
частей пропускается, если в реплее её нет. Части серверного реплея (`0000.wrpl`,
`0001.wrpl`, ...) читаются вместе как один бой; клиентский реплей и части серверного
реплея одного боя — это две записи, и они остаются двумя.

## Код завершения {#exit-status}

`0`, если все бои преобразованы, `1`, если какой-либо не удалось (остальные всё равно
преобразуются), `2`, если среди аргументов не найдено ни одного файла реплея.
