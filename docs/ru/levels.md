# Уровни (heat3d-wt-level) {#levels-heat3d-wt-level}

`heat3d-wt-level` превращает уровни вашей установки War Thunder в файлы `.glb` для
просмотрщика, в той же системе координат, что и таблицы реплеев.

## Пошагово {#step-by-step}

1. Выведите уровни вашей установки: `heat3d-wt-level list`. Команда печатает по одной
   строке на уровень: его название, рельеф и его карты, затем количество. Например
   (выдуманный уровень):

   ```text
   99_testmap    heightmap 2048x2048 @ 2 m, land mesh    maps: 99_testmap_map, 99_testmap_tankmap
   1 levels in C:\Games\War Thunder
   ```
2. Извлеките один, несколько (можно с масками) или все:

   ```bash
   heat3d-wt-level extract <level> -o levels
   heat3d-wt-level extract --all -o levels
   heat3d-wt-level extract <level> -o levels --detail high
   ```

3. Загрузите `levels/<level>/<level>.glb` в панели уровней просмотрщика, под боями этой карты.

Уровни, которые вы записываете, остаются на вашем компьютере: никогда не публикуйте их (см.
[Условия и лицензия](terms.md)).

## Параметры {#options}

![heat3d-wt-level extract --help](../assets/img/level-help.svg)

| Команда / параметр | Что делает |
|---|---|
| `list [--game FOLDER]` | каждый уровень в установке |
| `extract <levels...>` / `--all` | названные уровни (как их выводит `list`; можно с масками) или все уровни |
| `-o`, `--out` | папка результата; каждый уровень попадает в `<out>/<level>/` |
| `--game FOLDER` | папка War Thunder (по умолчанию находится через Steam или лаунчер; также `HEAT3D_WT_GAME`) |
| `--detail low/medium/high` | шаг сетки земли, цвет земли и бюджет объектов над танковой картой (по умолчанию `medium`) |
| `--max-object-triangles N` | бюджет объектов (по умолчанию — из уровня детализации) |
| `--max-grid N` | число выборок карты высот по стороне, для каждой части (по умолчанию 1024) |
| `--no-objects` | не включать здания, деревья и другие размещённые объекты |
| `--no-generated` | не включать объекты, которые создают классы земли (леса, города) |
| `--no-terrain-colour` | покрыть землю тактической картой, а не классами земли |
| `--no-texture` | оставить землю без текстуры |
| `--skip-existing` | пропустить уровни, у которых уже есть `.glb` |

## Что записывается {#what-is-written}

Каждый уровень превращается в `<out>/<level>/<level>.glb`, `<level>.json` (что было прочитано,
уровень воды, прямоугольники карт, количество треугольников, время) и тактические карты
уровня как `<level>_map.png` (воздушная карта) и `<level>_tankmap.png`; наземные карты также
получают `<level>_terrain.png` — собственные цвета земли поверх танковой карты. Файл glb
записывается в `<level>.glb.part` и переименовывается, когда готов; пока уровень записывается,
удерживается `<out>/<level>/.<level>.lock`, поэтому два извлечения никогда не пишут один и тот же
уровень (второе выводит `busy <level>`). Установка находится через Steam или папки по умолчанию у
лаунчера; иначе, где она лежит, указывают `--game <folder>` или `HEAT3D_WT_GAME`.

| Часть | Что это |
|---|---|
| `ground:<level>` | карта высот рельефа (`HM2`) как сетка; на наземных картах середина танковой карты (половина её ширины) с шагом `--detail`, окрашенная классами земли, наземными наклейками и дорогами (`<level>_terrain.png`; тактическая карта там, где это невозможно); на картах без танковой карты (воздушных) — вся карта высот с одним шагом (2048 выборок по стороне при `high`, иначе 1024), окрашенная классами земли над областью воздушной карты (4096 пикселей по стороне, около 32 м на пиксель на 131 км; тактическая карта там, где это невозможно); на уровнях без карты высот — земельная сетка |
| `ground:<level> tank map` | остальная часть танковой карты, с шагом вдвое грубее |
| `ground:<level> heightmap surroundings` | остальная часть карты высот, ещё грубее |
| `ground:<level> land mesh` | коллизионные треугольники земельной сетки там, где карта высот до них не доходит (окрестности танковой карты, на десятки километров); на уровнях без карты высот это земля, окрашенная как выше |
| `ground:<level> outside the map` | земля, которую изображение не покрывает, без текстуры |
| `water:<level>` | один плоский прямоугольник на `water_level` уровня поверх всего рельефа: игра рисует воду одной плоскостью, а низкая земля под ней — это морское, озёрное или речное дно |
| `water:<level> rivers` | на уровнях с водной картой высот (`WHM`) — наклонная водная поверхность по клеткам, которые она занимает |
| `structure:<level> buildings` | каждый размещённый объект, который не является растением: дома, руины, стены, заборы, мосты, рельсы, камни, реквизит. Неподвижные (`RIGz`) и, над танковой картой, те, что создают классы земли (городские кварталы, камни). Каждый рисуется своей сеткой для рендеринга (стены, крыши, проёмы окон, балки) на уровне детализации, который позволяет бюджет треугольников, окрашен по материалам средним цветом его диффузной текстуры |
| `structure:<level> trees` | деревья и кусты, неподвижные и созданные (леса, живые изгороди): их сетка для рендеринга там, где позволяет бюджет, иначе ствол и крона (конус для хвойных) цветом листвы самого дерева, в его настоящем размере |

У объектов без сетки для рендеринга вместо неё используется форма столкновения; у деревьев без
неё — крона. Цвета вершин (`COLOR_0`) хранят значения в кодировке sRGB, именно так их читает
просмотрщик 3DHeat.

**Координаты** — это метры игры с отражённой осью z: glb (x, y, z) = игра (x, y, -z). Мир игры
левосторонний (x — восток, y — вверх, z — север); glTF — правосторонний. `heat3d-wt-replay`
сохраняет z игры и сообщает просмотрщику, что её надо отразить, поэтому реплей и уровень его карты
ложатся друг на друга без шага размещения. JSON даёт прямоугольник каждой тактической карты в
метрах игры и её углы в системе glb, для загрузки PNG как изображения карты.

**Детализация.** `--detail low|medium|high` (по умолчанию medium) задаёт над танковой картой:

| | середина танковой карты | остальная танковая карта | цвет земли | бюджет объектов | больше всего треугольников на объект | сохраняемые растения |
|---|---|---|---|---|---|---|
| low | каждая 4-я выборка | каждая 8-я | 4 м на пиксель | 1.2 M | 1 500 | деревья 35 %, кусты 20 % |
| medium | каждая 2-я | каждая 4-я | 2 м | 3.5 M | 4 000 | деревья 70 %, кусты 50 % |
| high | каждая выборка (2 м на большинстве наземных карт) | каждая 2-я | 1 м (не более 4096 пикселей по стороне) | 4.5 M | 12 000 | все |

Два кольца танковой карты удерживаются в 0.3 M (low), 1 M (medium) и 3.7 M (high) треугольниках:
на картах, где карта высот точнее 2 м, шаги удваиваются (сначала внешнее кольцо), пока не
уложатся, поэтому и там получается около 2 м.

Наземная карта при `high` получается около 8 миллионов треугольников (3.5 M земли, 4.5 M объектов)
и 250 МБ; при `medium` — около 4.5 M. Уровни детализации объектов — те, которые сама игра взяла
бы с одного расстояния просмотра: самый короткий, сумма которого укладывается в бюджет. Мелкий
реквизит первым переходит на грубые уровни, крупные здания — последними, по дальностям, которые
задали их авторы для каждого уровня (`lodDistance` в JSON); то, что этот шаг экономит сверх бюджета,
возвращается крупнейшим объектам. Грубый цвет земли (воздушные карты) сначала усредняет мозаичные
текстуры каждого класса земли до размера пикселя, чтобы плитки не давали муар. Если даже самые
грубые уровни не укладываются, деревья, которые дают наибольшую экономию, становятся кронами, а
затем самые мелкие типы опускаются (`leftOut`); ни один объект не рисуется коробкой (если есть
коллизионная форма, это собственная форма объекта). Созданные объекты прореживаются детерминированно
по виду (`density`), одни и те же при каждом запуске. `--max-object-triangles` переопределяет
бюджет, `--max-grid` (по умолчанию 1024) ограничивает более грубые части карты высот, `--no-objects`
убирает объекты, `--no-generated` — созданные, `--no-terrain-colour` покрывает землю тактической
картой, `--no-texture` оставляет её без текстуры.

`parts.objects` в JSON перечисляет экземпляры (неподвижные и созданные, по виду и классу земли),
сколько было нарисовано на каком уровне детализации (`drawnAs`), треугольники, расстояние уровня
детализации и секунды; `parts.heightmap.rings` — шаг и треугольники каждого кольца земли;
`parts.terrainColour` — классы земли и их цвета, дороги и наземные наклейки; `trianglesTotal`,
`glbBytes` и `secondsBy` — итоги.

## Что читается и насколько хорошо {#what-is-read-and-how-well}

| Часть | Статус |
|---|---|
| Двоичный файл уровня (`levels/<level>.bin`, `DBLD` 3x64): таблица блоков | проверено на каждом уровне |
| Карта высот (`HM2`, версии 0-2; версия 2 — это 8-битные значения в блоках, фрагменты Oodle или zstd) | каждый уровень, у которого карта высот версии 2 с фрагментами Oodle; проверено глазом по их тактическим картам (реки, долины, побережья и города совпадают) |
| Коллизия земельной сетки (`lmap`, её трассировщик лучей `LTdump`) | читается там, где есть у уровня (упаковано Oodle). Это поверхность столкновений игры, а не отрисованная сетка, поэтому она грубее там, где земля ровная |
| Цвет земли (классы земли `lmap` и карта весов, карта физики `LMp2`, сплайны `hspl`) | карты цветов классов земли и детальные текстуры (их средние цвета), взвешенные картой весов, индекс биома с шагом 1 м для индексированных классов земли, формы дорог и наземных наклеек карты физики — цветом текстуры их сплайна или материала, обрывы на крутых склонах. Проверено по танковым картам: дороги, города, озёра, лесные полосы и выходы скал совпадают. Формула цвета шейдера рельефа самой War Thunder в открытом исходном коде не опубликована; используется опубликованная движком (daNetGame) формула, которая получается насыщеннее тактической карты |
| Уровень воды | `water_level` из BLK уровня в `aces.vromfs.bin` (0, где его нет) |
| Водная карта высот (`WHM`: сетка плоских клеток и страниц 130x130 с 16-битными высотами) | читается там, где есть у уровня; её реки уклоняются вместе с землёй |
| Тактические карты | из `content/base/res/locations_maps.dxp.bin`, размещаются по `mapCoord0/1` и `tankMapCoord0/1` BLK; верх изображения — север |
| Размещённые объекты (`RIGz`: неподвижные экземпляры генератора экземпляров рендеринга) | каждый экземпляр, как матрица 3x4 из 16-битных значений или, на некоторых уровнях, из 32-битных (число байтов клетки определяет, каких); каждый байт каждой клетки учтён на проверенных уровнях |
| Созданные объекты (маски `RIGz` классов земли и ресурсы `LandClass`) | генератор игры, перенесённый: те же места, опробованные в том же порядке с теми же случайными числами, маски классов земли и исключений, объект, выбранный на каждом месте, его поворот, масштаб и смещение по высоте; сущности мозаики (городские кварталы) и посадки (леса, кусты, поля). Создаётся только над танковой картой. Приближено: высота и нормаль земли (по карте высот; игра трассирует луч), коробки исключений, которые игра регистрирует во время работы, и курс деревьев (игра привязывает его к палитре поворотов импостера) |
| Сетки для рендеринга (ресурсы `RendInst` в `content/*/res/*.grp`, материалы в `riDesc.bin`) | вершины и треугольники каждого уровня детализации (позиции float; индексы 16 или 32 бита, обычные или упакованные meshoptimizer), материал каждого элемента. Элементы-наклейки и билборды-импостеры не учитываются; прозрачные (стекло) сохраняются |
| Цвета объектов | по материалам — среднее его диффузной текстуры в малом mip (с весом альфы для листвы), из пакетов текстур установки: t0 для большинства шейдеров, первая детальная диффузная там, где t0 — наложение или маска. Один цвет на материал: объекты без текстуры |
| Формы столкновения (`<object>_collision`) | ресурсы столкновения версии потока 3, используются там, где у объекта нет сетки для рендеринга. Рисуется только то, в что попадают лучи игры (узлы `TRACEABLE`), а коробки, сферы и капсулы — только когда у ресурса нет сетки: остальное — грубые физические заглушки, которые выглядели бы как кубы вокруг объекта |
| Навигационная сетка (`Lnav`), отрисованная земельная сетка, трава, `spgz`, `stbl`, `d2co` | не читаются |

Уровни сжаты Oodle, который является проприетарным. Игра поставляет свою копию,
`<War Thunder>\win-arm64ec\oo2core_9_win64.dll` (обычная сборка x64), и загружается именно она;
`HEAT3D_OODLE=<dll or folder>` указывает на другую. Ничего из Oodle здесь не включено.

## Форматы и где они описаны {#formats-and-where-they-are-documented}

Gaijin опубликовал исходный код Dagor Engine по лицензии BSD 3-Clause
(github.com/GaijinEntertainment/DagorEngine). Читатели здесь написаны по нему; никакой игровой
код не декомпилировался. Каждый модуль называет исходные файлы, которым он следует:

- `vromfs.py`: `*.vromfs.bin` (заголовок `VRFs`/`VRFx`, тело zstd, первые и последние 16 байт
  которого XOR-ятся с фиксированным ключом, таблица имён и таблица смещений:
  `osApiWrappers/dag_vromfs.h`, `ioSys/vromfsLoad.cpp`, `supp/dag_zstdObfuscate.h`) и
  двоичный BLK (формы 1-5, с общей таблицей имён архива `\xff?nm` и словарём zstd:
  `ioSys/dataBlock/blk_serialize.cpp`, `blk_parser.cpp`, `blk_zstd.cpp`).
- `dxp.py`: пакеты текстур `DxP2` (`lib3d/texPackMgr2.cpp`) и заголовки DDSx
  (`sharedInclude/3d/ddsxTex.h`); DXT1/DXT5/BC7 декодирует Pillow.
- `dagorlevel.py`: двоичный файл уровня (`scene/loadLevel.cpp`), карта высот
  (`heightmap/heightmapPhysHandler.cpp`, `heightMapLand/compressedHeightmap.cpp`), трассировщик
  лучей земли (`landMesh/lmeshManager.cpp`, `landMesh/landRayTracerSoA4.cpp`) и водная карта
  высот (`fftWater/fftWater.cpp`).
- `rigen.py`: размещённые объекты (`rendInst/riGen/riGenData.h`, `rendInst/rendInstGen.cpp`,
  `rendInst/riGen/genObjUtil.h`).
- `landgen.py`: созданные объекты (`rendInst/rendInstGenLand.cpp`, `riGen/landClassData.h`,
  `riGen/genObjByMask.h`, `riGen/genObjByDensGridMask.h`, `riGen/genObjUtil.h`,
  `riGen/riGenData.h`, `riGen/multiPointData.h`, `riGen/riRotationPalette.h`,
  `rendInstGen.cpp` (`create`, `precomputeCell`, `generateCell`), `gameMath/objgenPrng.h`,
  `util/dag_roHugeHierBitMap2d.h`, `util/dag_hierBitMap2d.h`, `ioSys/dag_roDataBlock.h`,
  `ioSys/roDataBlk.cpp`, `gameRes/grpData.h`).
- `rendinst.py`: экземпляры рендеринга (`shaders/rendInstRes.cpp`, `shaders/dag_rendInstRes.h`,
  `shaders/matVdataLoad.cpp`, `shaders/shaderMesh.cpp`, `shaders/dag_shaderMesh.h`,
  `shaders/dag_shaderCommon.h`, `drv/3d/dag_consts_base.h`, `gameRes/gameResDescBin.cpp`) и
  кодек индексов meshoptimizer (`3rdPartyLibs/meshoptimizer/src/indexcodec.cpp`, MIT).
- `terrain.py`: цвет земли (`landMesh/lmeshManager.cpp`, `lmeshLandClasses.cpp`,
  `lmeshWeightAtlas*.cpp`, `lmeshRenderer.cpp`, `landMesh/shaders/land_weight_atlas.hlsli`,
  `land_weight_inc.dshl`, `biomes.dshl`, `daNetGame/shaders/land_aces.dshl`, `make_clipmap.dshl`,
  `physMap/physMapLoad.cpp`, `baseUtil/treeBitmap.cpp`, `levelSplines/levelSplines.cpp`).
- `collision.py`: пакеты ресурсов (`gameRes/grpData.h`) и ресурсы столкновения
  (`sharedInclude/gameRes/collResStream.h`, `gameRes/collisionGameResLoad.cpp`), треугольники
  которых хранятся как BVH из четырёхугольников (`daBVH/bvhIO.cpp`, `daBVH/dag_swBLAS_leaf.h`,
  `swBLASLeafDefs.hlsli`).

wt_ext_cli (Apache-2.0) читает те же архивы; он не нужен и не используется.
