# 命中、射撃、火災 {#hits-gunfire-and-fires}

命中、弾薬、火災の列がどこから来ているかを知りたい人向けです。確認は、方法と一致の度合いだけを示します。

## 射撃 {#gunfire}

ユニットに命中したすべての発射物は、リプレイに入っています（メッセージ 0xF0E9）。命中した瞬間の射手の位置にある `shot` の行で、`targetX/Y/Z` は命中点（命中したユニットを、その座標系での命中点で動かし、その姿勢で回したもの）、そこへの向き、`other` は命中したユニットです。外れた砲弾や弾丸は送られていません。それらはエンティティではなく、飛行中の武器のメッセージが持つのは、ロケット、ミサイル、爆弾、魚雷だけだからです。録画しているプレイヤーの残りの弾数（`ammo` の列）は、射撃のたびに減るので、その連射はわかりますが、その弾がどこへ行ったかはわかりません。重対空砲と砲兵は 1 発ずつの射撃を送ります（`gun_shot`、向きなし）。40 mm の対空砲は連射を送ります（`fire_start`、`fire_stop`）。

## 命中の結果 {#hit-outcomes}

地上のユニットへのすべての発射物の命中に伴って、サーバーは、そのユニットに宛てたメッセージ 0xF144（UnitOnHit）を送ります。これは 1 バイトの欄が 4 つで、4 つ目の欄のビットが、その命中が何をしたかを示します（`selfCheck.unitMessages.outcome_*`）:

| ビット | 意味 | 根拠 |
|---|---|---|
| 0x20 | 発射物自身の命中 | ほとんどは、5 ms 以内にそのユニットへの 0xF0E9 の命中を伴います。それがない場合は、爆発（爆風）を伴います |
| 0x01 | 貫通した（貫徹） | 0x02、0x04、0x08 を持つメッセージは、必ずこれも持ちます |
| 0x02 | 致命的な命中（クリティカルヒット） | ほとんどの致命的な命中の記録が持ちます。偶然よりずっと多い |
| 0x04 | 破壊 | ほとんどはキルの記録と、1 秒以内のそのユニットの死を伴います |
| 0x08 | 重大なダメージ | 致命的な命中の記録の一部が持ちます。それ以外はまれ |

`hitOutcome` は最も重いものを取ります: `kill`（0x04）、`critical`（0x02 または 0x08）、`penetration`（0x01）、`nonpenetration`（0x20 のみ）。命中は、そのユニットに対する、5 ms 以内で最も近い、まだ組み合わされていない 0x20 つきの 0xF144 と組み合わされます。ゲームの命中カメラは跳弾と非貫通を区別しますが、ここで見つけたどのビットや欄もそれはしません。最初の 3 バイトは命中ごとに変わり、意味は不明です。クライアントのリプレイは、録画しているプレイヤー自身の飛行機に対してだけ 0xF144 を送り、そのビットはすべて 0 です。飛行機と艦船の命中には結果がありません。

## 弾薬 {#ammunition}

（`selfCheck.unitMessages.ammunition`）

* **爆発するかどうか。** 爆発する砲弾は、射手の uid と命中の番号を持つ 0xF133（UnitOnExplosion）を送ります。それがある命中は `explosive`、それ以外は `kinetic` です。
* **砲とそのスロット。** 0xF0BD（UnitBulletRearm）は、次に装填された弾です。車両の武器の一覧での武器の番号、弾薬のスロット、残りの弾数を持ちます。手動の装填手の再装填は、命中の後、一定の再装填時間が経ってから来ます。自動砲のものは、その数分の 1 秒後に来ます。射手の命中は、車両、シグネチャー、連射ごとにまとめられます。あるまとまりは、その武器の命中の半分以上の後 20 秒以内に、一定の遅れで武器が弾を装填したときに、その武器のものとされます。`ammoSlot` は `weapon/slot` で、命中の前に装填されていたスロットです。プレイヤーが途中で弾薬を変えていなければ、撃たれたものと考えられます。機関銃は 0xF0BD を送りません。
* **砲弾。** キルの武器は砲弾の ID（`125mm_3bm46`）です。被害者に対する射手の最後の命中が、その射手のスロットにそれを与えます。砲の口径が一致する場合に限ります。その種類と口径は武器ファイルのもの（`bulletName`、`bulletType`、`caliber`。`apds_fs_*` は APFSDS、`heat_fs_*` は HEAT-FS、`he_*` は HE など）。
* **残りの口径。** スロットの武器のもの。機関銃のまとまりは、そのシグネチャーが持ちうる機関銃の口径が 1 つだけのものにします。それ以外は車両の主砲のものです。インストールがない（`--game`）場合、`explosive` / `kinetic` 以外の種類、名前、口径はわかりません。

見つかっていないもの: 跳弾。ほかにもいくつかのメッセージが、命中の射手と番号を持ちます（0xF0C2。おそらく命中カメラの、車両を貫く経路。0xF117、0xF13C、0xF13E）。それらはサイドカーに残され、解読されていません。非貫通は `nonpenetration` のままです。

## 車両の火災 {#vehicle-fires}

火災の車両は、すべてのクライアントに表示されます。サーバーは、その車両に対するエンティティのメッセージ（イベント `0a519c58`）を送ります。そこには、その車両で燃えている火災の一覧が入っており、一覧が変わるたびに送られます。火災ごとに、2 つの 16 ビットの ID（2 つ目はダメージモデルのノード）、その種類、そして火が付くまで −1 が入ります。命中で点いた火災には、その燃えている地点を車両の座標系（x は前、y は上、z は左）で示すメッセージも送られます。

行: 火災が一覧に現れると `fire_on`、なくなると `fire_off`。車両の位置に、`fireId`（`first:node`）、`fireKind`、そして命中で点いた火災には `fireLocalX/Y/Z`（前、上、右）がつきます。車両が一度死ぬと、その一覧は再び送られないことがよくあります。その火災は、残骸、エンティティ、またはリプレイのどれかの終わりまで続きます（`selfCheck.fires`）。

確認: 戦車の消火器の数が減るたびに、火災が一覧から 1 秒の何分の一かの間に消えました。火災の地点のほとんどは、それを点けた命中と同じ側にあります。種類は番号ですが、それが何を表すかはわかっていません。ノードがどの部分かもわかりません。飛行機はそのような一覧を送りません。火災の飛行機は読まれません。
