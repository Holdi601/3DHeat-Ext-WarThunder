# Перетворення повторів {#converting-replays}

Результат: один файл `.3dheat` на бій (за замовчуванням) або окремі файли з
опцією `--loose`.

## Крок за кроком {#step-by-step}

1. **Увімкніть запис повторів.** War Thunder зберігає клієнтські повтори в папці
   `Replays` гри, якщо в її налаштуваннях увімкнено збереження повторів, наприклад
   `C:\Program Files (x86)\Steam\steamapps\common\War Thunder\Replays`.
   Серверний повтор, збережений зі сторінки повторів гри (zip з `0000.wrpl`,
   `0001.wrpl`, ...), теж можна перетворити.
2. **Відкрийте термінал** у папці, куди можна записувати результати
   ([Перш ніж почати](before-you-start.md)).
3. **Перетворіть:**

   ```bash
   heat3d-wt-replay "<War Thunder>/Replays" -o out
   heat3d-wt-replay a.wrpl b.wrpl -o out           # файли, папки або і те, і те
   heat3d-wt-replay battle.zip -o out              # zip серверного повтору
   heat3d-wt-replay a.wrpl -o out --loose          # окремі файли замість одного .3dheat
   ```

   `out` створюється в папці, де відкрито ваш термінал.
4. **Прочитайте, що пише програма.** Ви маєте побачити по одному рядку на бій.
5. **Відкрийте результат:** завантажте `out/<map>/<match>.3dheat` у переглядачі
   3DHeat ([Як завантажити один файл](https://holdi601.github.io/3DHeat/container.html#loading-one)).

![Запуск на синтетичному повторі: один .3dheat, --loose, пошкоджений файл, порожня папка](../assets/img/convert.svg)

На малюнку показано запуск на повторі, який тести будують у коді (справжнього
повтору і встановленої гри немає):

- `ok <file>`: бій перетворено (з `--loose`: `ok <table> <match document>`);
- `failed <file>: <why>`: файл не вдалося прочитати (статус виходу 1; решта
  все одно перетворюється);
- `no .wrpl files given`: нема чого перетворювати (статус виходу 2);
- `note: ...`: наприклад, що для назв техніки не знайдено встановлення War Thunder.

## Опції {#options}

| Опція | За замовчуванням | Що робить |
|---|---|---|
| `replays` (один або більше) | - | файли `.wrpl`, папки з них (сама папка, не її підпапки) або zip-архіви з ними (серверний повтор: його частини `.wrpl` розпаковуються в тимчасову папку) |
| `-o`, `--out` | обов'язково | куди писати: усередині папка на кожну карту |
| `--game FOLDER` | знаходиться автоматично | папка War Thunder, з текстів якої беруться назви техніки, зброї і боєприпасів, а з таблиць — ціни для [економіки](economy.md); також `HEAT3D_WT_GAME` |
| `--no-smoothing` | вимкнено | зберігати для інших юнітів обчислені за інерцією та отримані відліки такими, якими вони є в повторі ([Інерційне обчислення](aircraft.md#dead-reckoning-and-the-smoother)) |
| `--container` | увімкнено | пакувати кожен бій в один файл `.3dheat` |
| `--loose` | вимкнено | зберігати кожен бій окремими файлами (таблиця, документ матчу, супутні файли) |
| `--version` | - | вивести `heat3d-wt-replay <version>` і зупинитися |
| `-h`, `--help` | - | вивести опції і зупинитися |

Бій, перетворений повторно, записується знову. Опції, як їх виводить програма:
[Довідка з командами](../cli-reference.md).

## Які файли — це один бій {#which-files-are-one-battle}

Кожен бій стає одним файлом
`out/<map>/<map>_<AB|RB|SB>_<mode>_<start, UTC>_<session id>.3dheat`. AB, RB і SB —
це короткі позначення гри для аркадних, реалістичних і симуляторних боїв;
`<mode>` — режим місії, як його називає гра (`Conq4` — Conquest #4, `Dom` —
Domination, `Bttl` — Battle; див. [Режим бою](ground.md#battle-mode)); будь-яка з
цих частин пропускається, якщо в повторі її немає. Частини серверного повтору
(`0000.wrpl`, `0001.wrpl`, ...) читаються разом як один бій; клієнтський повтор
і частини серверного повтору того самого бою — це два записи, і вони лишаються двома.

## Статус виходу {#exit-status}

`0`, коли всі бої перетворено; `1`, коли якийсь не вдався (решта все одно
перетворюються); `2`, коли серед аргументів не знайдено жодного файлу повтору.
